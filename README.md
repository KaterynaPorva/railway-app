# Лабораторна робота 1 з ООП

## Завдання
Створити консольний додаток, що відповідає наступним вимогам:
* Використовувати можливості ООП: класи, успадкування, поліморфізм, інкапсуляція.
* Кожен клас повинен мати змістовну назву та інформативне наповнення.
* Успадкування повинно застосовуватися лише тоді, коли це має сенс.
* При кодуванні використати оформлення коду відповідно до Java Code Convention.
* Класи повинні бути коректно розподілені по Java-пакетах.
* Робота з консоллю або консольне меню повинно бути мінімальним.
* Для збереження параметрів ініціалізації можна використовувати файли.
* Весь код повинен бути покритий Unit-тестами. Використовувати JUnit 4 або 5.
* Код повинен бути розміщений на віддаленому репозиторії. Історія змін повинна мати логічні commit-повідомлення, репозиторій має мати правильно налаштований gitignore файл.

**Варіант 8:** Транспорт. Визначити ієрархію рухомого складу залізничного транспорту. Створити пасажирський поїзд. Порахувати загальну кількість пасажирів і багажу. Провести сортування вагонів поїзда на основі рівня комфортності. Знайти вагони в поїзді, що відповідають заданому діапазону параметрів кількості пасажирів.

## Реалізація

**Ієрархія вагонів:**
* `PassengerCarriage` (абстрактний): ідентифікатор вагона, кількість пасажирських місць, вантажопідйомність багажу, рівень комфорту (`ComfortLevel`).
* `EconomyCarriage`: плацкартний вагон (рівень `ECONOMY`).
* `CompartmentCarriage`: купейний вагон (рівень `COMPARTMENT`).
* `SleepingCarriage`: спальний вагон/СВ (рівень `VIP`).

**Структура поїзда та логіка:**
* `PassengerTrain`: зберігає номер поїзда та список прикріплених до нього вагонів.
* `TrainService`: сервісний клас на базі Java Stream API, що виконує підрахунки, сортування та фільтрацію вагонів.
* `Main`: головний клас програми для демонстрації роботи логіки.

**Особливості ініціалізації даних (Відсутність роботи з файлами):**
Відповідно до вимог, у даному проєкті обрано підхід прямої ініціалізації об'єктів (In-Memory) безпосередньо в коді (`Main.java`). Робота із зовнішніми текстовими файлами не використовується з таких причин:
1. **Уникнення overengineering:** Для роботи пряма ініціалізація дозволяє зберегти прозорість коду.
2. **ООП:** Основна увага приділена побудові правильної ієрархії класів, поліморфізму та обробці колекцій через Stream API, а не парсингу текстових рядків та обробці винятків вводу/виводу.

## Тести

* **Фреймворк:** JUnit 5.
* **`TrainServiceTest`**: містить 5 тестів, які покривають логіку програми:
  * Успішне додавання вагонів до списку поїзда.
  * Валідація математики підрахунку загальної кількості пасажирів.
  * Валідація математики підрахунку вантажопідйомності багажу.
  * Перевірка коректності сортування Enum-рівнів комфорту.
  * Перевірка фільтрації вагонів за заданими межами пасажирських місць.

## Запуск програми та тестів

**Для запуску головного класу:**

```bash
mvn exec:java -Dexec.mainClass="ua.knu.transport.Main"
```

**Для запуску Unit-тестів:**

```bash
mvn test
```
